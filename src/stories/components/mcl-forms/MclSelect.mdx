# MCL Select

Included in `@bobbykim/mcl-forms`

## Installation

```sh
npm i @bobbykim/mcl-forms
```

## Usage

`MclSelect` is a filterable combobox built on the ARIA list-autocomplete
pattern. `options` is required, and takes either `string[]` or
`{ text, value }[]` — `text` is displayed, `value` is what the model carries.

```js
<script setup lang="ts">
import { MclSelect } from '@bobbykim/mcl-forms'
import { ref } from 'vue'

const selected = ref<string | number | null>(null)
const options = [
  { text: 'Item 1', value: 'value-1' },
  { text: 'Item 2', value: 'value-2' },
]
</script>

<template>
  <mcl-select v-model="selected" :options="options"></mcl-select>
</template>
```

Opening the list shows every option with the current selection marked, and
narrows only once the user types. Arrow keys move the highlight, `Enter`
commits it, `Escape` closes.

## The model holds the value, not the label

The visible input's text is the display label, so the submitted value lives on
a separate hidden input carrying `value`. That hidden input is rendered only
when a `name` exists — a select with no name contributes nothing to a form.

## Positioning

The listbox is placed by floating-ui, so it flips above the input rather than
being clipped when there is no room below.

## Field state

`id`, `name`, `invalid`, `required` and `disabled` are inherited from a
surrounding [MclFormGroup](?path=/docs/components-form-mclformgroup--docs)
when omitted. Leaving `invalid` unset is different from setting it `false`:
unset inherits, `false` overrides. Disabling the control also closes an open
listbox, so a form that disables itself on submit cannot leave one behind that
still commits on click.

This control renders its own error region, gated on `invalid` — so
`invalid-feedback` on its own renders nothing.

## Events

| Event     | Payload                   | Fired when                                 |
| --------- | ------------------------- | ------------------------------------------ |
| `open`    | —                         | the listbox opens                          |
| `close`   | —                         | the listbox closes, by any route           |
| `clear`   | —                         | the clear button empties the selection     |
| `select`  | `value: string \| number` | an option is committed by click or `Enter` |
| `changed` | `value: string \| number` | the model changes, including from outside  |

`select` fires only on a user commit; `changed` follows any model change, so a
parent writing the model programmatically triggers `changed` alone.

## Slots

### `#dropdown`

Replaces the rendering of the option list. Taking this over means taking over
the combobox semantics with it: `role="option"` and the `optionId(index)` id
are what `aria-activedescendant` points at, so omitting them leaves keyboard
users with an unannounced list.

| Prop          | Type                                                                      | Description                                                               |
| ------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `options`     | `(string \| SelectOptionType)[]`                                          | the currently visible options, already filtered                           |
| `activeIndex` | `number`                                                                  | index of the highlighted option, or `-1` for none                         |
| `optionClick` | `(option: string \| SelectOptionType) => void`                            | commits an option. Takes the option alone — it is not an event handler    |
| `setRef`      | `(el: Element \| ComponentPublicInstance \| null, index: number) => void` | registers each option element so the active one can be scrolled into view |
| `hover`       | `(index: number) => void`                                                 | moves the highlight, for pointer hover                                    |
| `optionId`    | `(index: number) => string`                                               | the element id this option must carry                                     |

#### Example

```vue
<template>
  <mcl-select v-model="selected" :options="options">
    <template
      #dropdown="{ options, activeIndex, optionClick, setRef, hover, optionId }"
    >
      <li
        v-for="(option, index) in options"
        :id="optionId(index)"
        :key="index"
        :ref="(el) => setRef(el, index)"
        role="option"
        :aria-selected="option === selected"
        :class="{ active: index === activeIndex }"
        @click="optionClick(option)"
        @mouseenter="hover(index)"
      >
        {{ option }}
      </li>
    </template>
  </mcl-select>
</template>
```

### `#no-match`

Replaces the "no match" content. This region is a `role="status"` element
outside the listbox, not an option in it, so its content is plain markup
rather than an `<li>`.

### `#invalid-feedback`

Replaces the rendered error text. Still gated on `invalid`.
