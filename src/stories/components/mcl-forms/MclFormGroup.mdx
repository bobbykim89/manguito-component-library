# MCL Form Group

Included in `@bobbykim/mcl-forms`

## Installation

```sh
npm i @bobbykim/mcl-forms
```

## Usage

`MclFormGroup` labels a field and publishes shared state to the controls
inside it. A control placed in a group does not need an `id` — it inherits the
group's, which is what binds the label to it.

```js
<script setup lang="ts">
import { MclFormGroup, MclInputText } from '@bobbykim/mcl-forms'
import { ref } from 'vue'

const name = ref<string>('')
</script>

<template>
  <mcl-form-group field-id="full-name" label="Full name">
    <mcl-input-text v-model="name"></mcl-input-text>
  </mcl-form-group>
</template>
```

## Two labelling modes

`group-label` decides the rendered structure, and with it how ids are
resolved:

| Mode          | Renders                     | Descendant ids                                                  |
| ------------- | --------------------------- | --------------------------------------------------------------- |
| default       | `<label for>` + one control | every control reuses the group's id, so the label binds to it   |
| `group-label` | `<fieldset>` + `<legend>`   | each control generates its own id, so a set can share one label |

Use `group-label` for radio and checkbox sets. Because there is no single
`for` to point at, put each control **inside** its own `<label>` rather than
beside it.

## Cascading state

`invalid`, `required` and `disabled` are inherited by every control in the
group. Each is `boolean | undefined`, and `undefined` is meaningful: it means
"inherit". A control that sets the prop itself always wins, so
`:invalid="false"` on a control stays valid no matter what the group says.

## Help text

through `aria-describedby`. The `#help` slot replaces the rendered content.

## Error region ownership

Passing `invalid-feedback` — or filling the `#invalid-feedback` slot — makes
the **group** own the error region. Its controls then render none of their own
and point `aria-describedby` here instead, so exactly one element carries the
message.

Two things to know about it:

- Ownership is decided once, at setup, from the _presence_ of the prop or
  slot rather than from its value. Bind it to a string and use `''` for "no
  error yet" — `:invalid-feedback="errors.email"` with `errors.email`
  undefined at mount leaves the group not owning the region, and its message
  never renders.
- A group that owns the region **must carry `invalid` itself**. The region
  renders off the group's own `invalid`, and the controls have already skipped
  theirs, so an invalid control inside a group with `:invalid="false"` shows no
  message anywhere.

## Slots

- `#label`: replaces the rendered label text
- `#help`: replaces the rendered help text
- `#invalid-feedback`: replaces the rendered error text, and — like the
  `invalid-feedback` prop — makes the group own the error region
