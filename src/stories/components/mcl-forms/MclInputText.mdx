# MCL Input Text

Included in `@bobbykim/mcl-forms`

## Installation

```sh
npm i @bobbykim/mcl-forms
```

## Usage

```js
<script setup lang="ts">
import { MclInputText } from '@bobbykim/mcl-forms'
import { ref } from 'vue'

const inputData = ref<string>('')
</script>

<template>
  <mcl-input-text v-model="inputData"></mcl-input-text>
</template>
```

## Field state

`id`, `name`, `invalid`, `required` and `disabled` are inherited from a
surrounding [MclFormGroup](?path=/docs/components-form-mclformgroup--docs)
when omitted. Leaving `invalid` unset is different from setting it `false`:
unset inherits, `false` overrides.

`name` deliberately has no id fallback: an input with no `name` of its own and
no group to inherit one from contributes nothing to a form post, rather than
posting under a generated id.

## Invalid feedback

This control renders its own error region. It appears only while `invalid`
resolves true — the region is conditional so that `role="alert"` announces on
insertion, which means `invalid-feedback` on its own renders nothing.

When a surrounding group owns the error region, this control renders none and
its `invalid-feedback` is ignored.
