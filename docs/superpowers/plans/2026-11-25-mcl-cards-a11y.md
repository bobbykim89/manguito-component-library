# mcl-cards Accessibility Fixes (#129) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix all 21 findings in #129. Card C can be operated with a keyboard and a screen reader, every card exposes correct semantics, and the `mcl-cards` stories pass `a11y: { test: 'error' }`.

**Architecture:**

- Each card's whole-card action becomes a real `<button>` or `<a>` stretched over the card with an `::after` overlay. Slot content sits above the target and passes plain-text clicks through to it.
- Two small internal constants hold the shared class strings: the stretched target and the slot pass-through.
- CTAs render as `<a>` only when `ctaAsLink` is true, and as `<button type="button">` otherwise.
- Heading level is set by a `titleLevel` prop.
- Unit tests in jsdom cover the DOM contract. Storybook `play` tests in Chromium cover keyboard use and pointer hit-testing, which jsdom can't do.

**Tech Stack:** Vue 3.5 SFCs (`<script setup lang="ts">`), Tailwind v4 classes, Vitest + `@vue/test-utils` (jsdom), `@mcl/test-utils/ssr` (`hydrate`), Storybook 10 `play` functions with `storybook/test`, Changesets.

**Spec:** `docs/superpowers/specs/2026-11-25-mcl-cards-a11y-design.md`

## Global Constraints

- Branch: `feat/129-cards-a11y` (it holds the spec commit). Never push to `master`.
- Event names, `card-click` and `card-btn-click`, and the payload `CardClickEvent { title, url, target? }` must not change.
- Default heading level is `'h3'`. The prop is `titleLevel?: HeadingLevel`, using `HeadingLevel` from `@bobbykim/manguito-theme`, rendered with `<component :is="titleLevel">`. Size classes stay independent of the level.
- The default for `imageAlt` is `''` on Card A, Card B and Card C. Each card's `imageAlt` prop gets a JSDoc line: "Pass alt text for meaningful images; leave empty only for decorative ones."
- Spec Decision 12's server check is done with `hydrate()` from `@mcl/test-utils/ssr` inside `MclCardC.test.ts` (jsdom). It server-renders and then hydrates, which covers a node-only `*.server.test.ts`. `@mcl/test-utils` is already a root devDependency, as `manguito-theme`'s tests use it.
- The new-tab cue appears when target is `_blank`. It's exactly `<span class="sr-only"> (opens in a new tab)</span>`, placed inside the link.
- IDs referenced by `aria-*` come from Vue `useId()`.
- The focus indicator for new interactive elements is the #122 `mcl-focus-ring` utility, applied with `focus-visible:`.
- Under `prefers-reduced-motion: reduce`:
  - Card C's flip rotation and transitions are off.
  - Card A's `enlargeOnHover` has `motion-reduce:transition-none motion-reduce:hover:scale-100`.
- The look stays the same. A CTA that changes from `<a>` to `<button>` keeps the same classes, plus any reset needed so it renders identically.
- Do not export new public API. The shared constants stay internal and are not re-exported from `lib/index.ts`.
- Unit tests run in jsdom. Pointer hit-testing and real keyboard activation are proven only in Storybook `play` tests (`pnpm test:storybook`).
- Commit messages are conventional and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Run `pnpm format` before each commit.

## Review Focus

1. **Clicking plain slot text still triggers the card.** This depends on how the browser decides what was clicked, so jsdom can't prove it. It's pinned by browser `play` tests in Task 1 (Card C) and Task 2 (Card A).
2. **A link or button inside a slot never also fires the card's event.** Pinned by unit tests in Tasks 1–3.
3. **Card C's content before the flip can't be focused.** A slot link must not get a Tab stop until the card flips. Pinned by the Task 1 `play` test.
4. **Card C with an empty `title`** still gets an accessible name (the fallback). Pinned by a Task 1 unit test.
5. **Server-rendered IDs.** Card C's `aria-controls` and `aria-labelledby` must still resolve after hydration, with no hydration warnings. Pinned by a Task 1 hydration test.

**Interfaces:**

- Produces, in `lib/common/a11y.ts` (internal, not exported from `lib/index.ts`):
  - `export const stretchedTargetClass: string`. Tailwind classes that make an element's `::after` cover its nearest positioned ancestor: `after:absolute after:inset-0 after:content-['']`, plus `focus-visible:outline-none focus-visible:after:mcl-focus-ring` so the ring draws around the card.
  - `export const slotPassThroughClass: string`. `pointer-events-none`, plus `pointer-events-auto` on descendant `a, button, input, select, textarea, label, [tabindex]`, written with arbitrary variants such as `[&_a]:pointer-events-auto`. It also sets `relative z-10`, so slot content sits above the stretched target.

- [ ] **Step 3: Create `lib/common/a11y.ts` and rewrite `MclCardC.vue`**

**Props:**

- Add `titleLevel?: HeadingLevel` (default `'h3'`).
- Change the default of `imageAlt` to `''`.
- The other props and the emit signature stay the same.

**Markup:**

- **Root:** `<div class="card relative …">` with no `@click`.
- **The button:**
  - A `<button type="button">` that is the root's first child, with an empty body.
  - Classes: `stretchedTargetClass`, plus `absolute inset-0` (or the `::after` alone).
  - Attributes: `:aria-expanded="cardFlipped"`, `:aria-controls="contentId"`, and either `aria-labelledby` (pointing to the title id) or `aria-label`.
  - `@click="handleCardClick"`.
- **Content region:** a `<div :id="contentId" :inert="!cardFlipped">` that wraps the image and the text block. It uses `slotPassThroughClass`.
- **Title:** rendered with `<component :is="titleLevel" :id="titleId">`.

**`handleCardClick(e: Event): void`:**

- If the card is already flipped, emit `card-click` with `e`.
- Otherwise, set `cardFlipped = true`.
- Never call `preventDefault`.

**Reduced motion:** wrap the `.flip-card` transform and the `duration-*` classes so they don't apply under `prefers-reduced-motion: reduce`. Use `@media (prefers-reduced-motion: reduce)` in the scoped SCSS and `motion-reduce:` utilities.
