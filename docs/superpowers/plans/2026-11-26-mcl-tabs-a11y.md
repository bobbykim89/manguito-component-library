# mcl-tabs Accessibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve every finding in #132, so `MclTabsA`'s tabs work with a keyboard and a screen reader and its scroll buttons stop trapping or losing focus. Then switch its stories to `a11y: 'error'`.

**Architecture:**

- All component changes are in `MclTabsA.vue`.
- **Tabs.** They bind the base `tabAttrs(idx)` from #128. That gives each tab its id, role, selection state, a roving tabindex, click selection and the arrow keys. `MclTabsA` adds its own `aria-controls`, so the link to the panel is in the server HTML, plus `tab-click` emission and the visual classes.
- **Scroll buttons** become mouse- and touch-only helpers, hidden from assistive technology.
- Stories, docs and a changeset close the issue.

**Tech Stack:** Vue 3.5 SFC, `@vueuse/core`, Vitest + jsdom (`@mcl/test-utils/ssr` `hydrate` / `renderOnServer`, `@vue/test-utils` `mount`), Storybook 10 play tests with axe.

**Spec:** `docs/superpowers/specs/2026-11-26-mcl-tabs-a11y-design.md`

## Global Constraints

- **Package scope.** Only `@bobbykim/mcl-tabs`, its stories and docs change. No changes to `src/components/manguito-theme`.
- **Unchanged for mouse users.**
  - A click on an unselected tab selects it and emits `tab-click(event, title)`.
  - The scroll buttons scroll by 100px and show only when there's more to scroll to (`v-if`, as today).
  - Visual classes stay the same, apart from the focus ring and the title element.
- **`tab-click` payload** stays `(event: Event, title: string)`. It fires on every selection change:
  - from a click, with the `MouseEvent`;
  - from a key, with the `KeyboardEvent`.

  It never fires for the already-selected tab, or for keys that don't change the selection.

- **Hidden elements never hold focus.** No element with `aria-hidden="true"` may ever be focused.
- **Focus ring.** The class is `focus-visible:mcl-focus-ring`, and it replaces `focus:outline-none` on the tabs.
- **Changeset.** `.changeset/mcl-tabs-a11y.md` is a **minor** bump for `@bobbykim/mcl-tabs`. It must say:
  - the titles are no longer headings;
  - the scroll buttons are hidden from assistive technology and out of the Tab order;
  - keyboard selection also emits `tab-click`;
  - the release needs the pending `manguito-theme` minor (`manguito-theme-a11y`), and the two publish together.
- **Commits.** Use conventional commit messages ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Test conventions

- **Tests and helpers.**
  - Tests go in `src/components/mcl-tabs/lib/mcl-tabs-a/MclTabsA.test.ts` and `MclTabsA.server.test.ts`.
  - Fixture: `content3 = [TAB-ONE, TAB-TWO, TAB-THREE]` with `tabName: 'demo'`, so panel `i` is `#demo-tab-${i}`.
  - Helper: `tabs(root)` returns `root.querySelectorAll('[role="tab"]')`.
- **Keys** are dispatched keydown-only: `new KeyboardEvent('keydown', { key, bubbles: true, cancelable: true })` on `document.activeElement`. Then `await nextTick()` twice, because the base moves focus in a `nextTick`.
- **Mounting.** Use `mount(MclTabsA, { props, attachTo: document.body })`, and unmount in `afterEach`. Pass `global: { stubs: { transition: false } }` whenever a test checks which panel shows.
- **Test command:** `pnpm exec vitest run src/components/mcl-tabs`

## Review Focus

1. **Enter or Space on the focused, selected tab** (it arrives as a click). No `tab-click` fires, focus stays, and the panel is unchanged. Pinned in Task 1.
2. **Two ArrowRight presses in a row.** Two `tab-click` events, each with the title of the tab it selected, in order. Pinned in Task 1.
3. **A tab set with a single tab.** Arrows, Home and End don't throw and emit nothing. Pinned in Task 1.
4. **Pressing a scroll button with the mouse while a tab has keyboard focus.** The `mousedown` is prevented, so focus stays on the tab and is never moved to the `aria-hidden` button. Pinned in Task 2.
5. **Server HTML.** Each tab's `aria-controls` equals its panel's `id` before any client code runs. Pinned in Task 1.

  Run: `pnpm exec vitest run src/components/mcl-tabs`

- [ ] **Step 3: Implement in `MclTabsA.vue`**
  - **Bindings on each tab `<button>`:**
    - `type="button"`, then `v-bind="tabAttrs(idx)"`, then `:aria-controls="generateTabId(idx)"`. The explicit binding comes after `v-bind`, so it wins.
    - Remove the hand-written `role`, `:aria-selected`, `:tabindex` and `:disabled`, and the `update(idx)` call. The base `onClick` selects.
    - Replace `focus:outline-none` with `focus-visible:mcl-focus-ring`.
  - **`@click="onTabClick($event, idx, activeTab)"`** emits only when `idx !== activeTab`. `activeTab` is the render-time slot value, so it is still the old selection.
  - **`@keydown="onTabKeydown"`**
    - If `!e.defaultPrevented`, return. That means the base didn't handle the key.
    - Otherwise wait two `nextTick`s, then emit `tab-click(e, content[i].title)`, where `i` is the index of `document.activeElement` among this component's `[role="tab"]` elements.
    - This reads the base's result rather than repeating its key logic.
    - With a single tab, the base still prevents, but the focused index doesn't change from the starting one. Emit only when it differs.
  - **Titles:** the `<h3>` becomes `<span class="block" :class="generateClass.h3Variant({ size: titleSize })">`.
