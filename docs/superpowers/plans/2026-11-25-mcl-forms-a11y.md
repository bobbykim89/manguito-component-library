# mcl-forms Accessibility Fixes (#130) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix all 14 findings in #130, so every `mcl-forms` control is correctly named, labelled and announced, and the `mcl-forms` stories pass `a11y: { test: 'error' }`.

**Architecture:**

- **The field context does the id and label wiring.** `lib/common/fieldContext.ts` gains three things:
  - the label's own id
  - a way for a control to report its resolved id to the group
  - a toggle flag that turns off label naming and fieldset `required` inheritance
- **One new internal composable** splits each control's `$attrs`: `class` and `style` go on the wrapper, everything else on the focusable element. It also resolves the control's `aria-labelledby`.
- **`MclSelect`** opens on the chosen option, moves `aria-selected` to the highlighted option, names its listbox, and keeps a live status region mounted.
- **Stories** are fixed and set to `'error'`. A browser `play` test proves that clicking the label focuses a control that has its own id.

**Tech Stack:** Vue 3.5 SFCs (`<script setup lang="ts">`, `defineOptions`, `useAttrs`, `useId`), Tailwind v4, Vitest + `@vue/test-utils` (happy-dom for this package), `@mcl/test-utils/ssr` (`hydrate`, needs a jsdom file), Storybook 10 `play` with `storybook/test`, Changesets.

**Spec:** `docs/superpowers/specs/2026-11-25-mcl-forms-a11y-design.md`

## Global Constraints

- **Branch:** `feat/130-forms-a11y` (it holds the spec commit `da4fd10`). Never push to `master`.
- **Release:** `@bobbykim/mcl-forms` is at `0.13.0` and gets a **minor** bump. One changeset, `.changeset/mcl-forms-a11y.md`.
- **No new public exports.** Nothing is added to `lib/index.ts`; the composable and the context additions stay internal.
- **Ids and labels:**
  - IDs referenced by `aria-*` come from the existing resolver (`resolveFieldId` / `useId`). The label id is `` `${group.id}-label` ``.
  - The server render and the client's first render must give the label the same `for` (the group's id). A reported control id may only change it in a later render.
  - A consumer's `aria-label` or `aria-labelledby` on a control always beats the group's `aria-labelledby`.
- **Owned attributes:** the component's value always wins for `id`, `name`, `type`, `role`, `required`, `disabled`, `aria-invalid`, `aria-describedby`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-required`. For every other attribute the consumer's value wins.
- **Required text (exact):**
  - Visible marker: `<span aria-hidden="true"> *</span>` after the label content, inside the `<label>` or `<legend>`.
  - Fieldset mode adds `<span class="sr-only"> (required)</span>`.
- **Toggles** are `MclCheckbox`, `MclInputRadio` and `MclInputSwitch`:
  - none of them get the group's `aria-labelledby`
  - `MclCheckbox` and `MclInputSwitch` don't inherit `required` from a fieldset-mode group
  - radios still inherit it
- **Reduced motion:** `motion-reduce:transition-none`, or `motion-reduce:before:transition-none` where the transition is on `::before`.
- **The look stays the same.** The only intended visual changes are the required asterisk and the chosen option being highlighted when a select opens.
- **Unit test command:** `pnpm vitest run --project '!storybook*' src/components/mcl-forms`. This package's tests run in happy-dom. A test that calls `hydrate()` goes in its own file starting with `// @vitest-environment jsdom`.
- **Commits:** conventional messages ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Run `pnpm format` before each commit and `pnpm lint` before each task's commit.

## Review Focus

1. **The group's `label` becomes `''` after mount.** The label element disappears, so the control's `aria-labelledby` must disappear too, not dangle. Pinned in Task 1.
2. **A control mounted client-only (no SSR) with its own id.** After one tick, the label's `for` equals the control's id. Pinned in Task 1.
3. **A consumer `aria-label` on a control inside a labelled group.** It wins, and no `aria-labelledby` is set. Pinned in Task 2.
4. **`MclSelect` opened by ArrowDown, not by focus, while a value is chosen.** The list still starts on the chosen option, and that survives the filter reset that happens on open. Pinned in Task 4.
5. **A required group with a custom `label` slot.** The asterisk still renders after the slot content. Pinned in Task 1.

**Interfaces:**

- Produces, in `FieldContext`:
  - `labelId: ComputedRef<string | undefined>`. On the group's own context, it is `` `${id}-label` `` while the group renders a label (`label` non-empty, or a `label` slot exists) in **label mode**; otherwise `undefined`.
  - `labelledBy: ComputedRef<string | undefined>`. On a control's context, it is the group's `labelId` when the control isn't a toggle and the group is in label mode; otherwise `undefined`.
  - `reportControlId: (id: string) => void`. On the group's context, it records the first id reported. On a control's context it is a no-op.
- Produces, in `FieldConsumerOptions`: `isToggle?: boolean` (default `false`). When true, `labelledBy` is always `undefined`. When `isToggle` is set and the group is in fieldset mode, `required` doesn't fall back to the group's value; the control's own prop or `false` decides it.
- `useFieldContext` calls `group.reportControlId(id)` during setup, only when the group is in label mode.
- `MclFormGroup`'s label renders `:for="reportedId ?? field.id"` and `:id="field.labelId.value"`. A reported id is applied after mount, so the first client render matches the server.
- Consumed by Tasks 2 and 4.
