Accessibility fixes for the base components (#128). Nothing is removed; the items marked "changes" alter output you may test against.

- **Tabs:** the `tab-button` slot also passes `tabAttrs(index)`. Bind it on each tab (`v-bind="tabAttrs(i)"`) to get its id, `role="tab"`, `aria-selected`, `aria-controls`, a roving `tabindex` (one Tab stop for the set), click selection, and Arrow Left/Right (wrapping), Home and End. A `TabContent` is labelled by its tab only when that tab binds `tabAttrs`, so tab sets that render their own tabs get no dangling reference. Changes: `TabContent` has `tabindex="0"` (was `-1`), so a panel with nothing focusable in it is reachable with Tab.
- **Dropdown:** the `toggler` slot also passes `attrs` (`aria-expanded`, and `aria-controls` pointing at the content, which now has an id). Escape, or an item calling `itemClick`, now returns focus to the toggler instead of dropping it on `<body>`; a click outside leaves focus where it went. Changes: Escape is handled on `keydown` (was `keyup`), only while the menu is open, and calls `preventDefault()`. `toggle()` may be called without an event.
- **Escape order:** inside a Modal, a Sidebar or HeaderVertical's open menu, an Escape that a component inside already handled (an open Dropdown, a showing tooltip) no longer also closes the overlay; the next Escape does.
- **Modal and Sidebar:** new `titleLevel` prop for the default title. Changes: the default is `h2` (was `h3`); the look is unchanged. A custom `header` that never renders the `titleId` heading no longer leaves a dangling `aria-labelledby`, and a dialog left with no accessible name logs a warning outside production.
- **HeaderVertical:** while open, the mobile menu is a modal dialog (`role="dialog"`, `aria-modal`, labelled by `navLabel`): focus is trapped in it, Escape closes it, and closing it from inside (Escape, `headerClose`) returns focus to the menu button.
- **HeaderHorizontal:** changes: one `<nav>` landmark now wraps both the bar and the mobile panel (the bar's former `<nav>` is a `<div>` with the same classes). Closing the panel from inside returns focus to the menu button. The `sticky` prop's docs explain setting `scroll-padding-top` so the header doesn't cover focused elements.
- **NavDrawer (menu button):** `type="button"`, a new `controls` prop rendered as `aria-controls` (both headers fill it), and the shared `focus-visible:mcl-focus-ring`. Changes: the hidden checkbox inside the button is gone (the icon follows `toggle`), and the old `focus:ring-4` ring that also showed on mouse click is replaced.
- **Alert:** dismissing it now moves focus to the new `returnFocus` prop (selector or element), else the next focusable element after the alert, else the one before, unless your `close` handler moved focus itself. New `live` prop: `'assertive'` (default, `role="alert"`) or `'polite'` (`role="status"`). Changes: the conflicting `aria-live="polite"` is gone.
- **Card:** changes: `imageAlt` defaults to `''`, so the image is decorative unless you set it; the title heading renders only when `title` is set. New `titleLevel` prop (default `h3`).
- **Carousel:** changes: `CarouselContainer` is a `role="region"` with `aria-roledescription="carousel"` and a new `ariaLabel` prop (default `'Carousel'`); the slide area is a polite live region. Each `CarouselContent` is `role="group"` with `aria-roledescription="slide"` and an "n of m" label (was `role="tabpanel"`).
- **vTooltip:** changes: the tooltip's id is added to the host's existing `aria-describedby` instead of replacing it, and unmounting removes only that id. Escape hides a showing tooltip until the next hover or focus.
- **`.mcl-list`:** the CSS notes that the list needs `role="list"` to keep its list semantics in WebKit/VoiceOver.
